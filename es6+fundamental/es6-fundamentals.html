Bài 1 · Variables

let, const và
tại sao var là vấn đề

Hiểu sự khác biệt về scope và mutability — foundation của mọi code JS hiện đại.

Cũ — tránh dùngvar — function scope, bị hoisting

var tồn tại trong phạm vi function, không phải block. Bị hoisting — khai báo đưa lên đầu nhưng giá trị thì không. Tạo ra bugs khó debug.

var — behaviour nguy hiểm
// 1. Hoisting — không báo lỗi dù dùng trước khai báo
console.log(name); // undefined (không phải lỗi!)
var name = 'Nam';

// 2. Không có block scope — if/for không tạo scope mới
if (true) {
  var secret = 'leaked!';
}
console.log(secret); // 'leaked!' — thoát ra ngoài block

// 3. Re-declare không báo lỗi
var user = 'Alice';
var user = 'Bob'; // JS không phàn nàn
ES6 · Dùng thay thếlet — block scope, re-assignable

let chỉ tồn tại trong block {} gần nhất. Có thể thay đổi giá trị nhưng không thể re-declare trong cùng scope.

let — block scope
let count = 0;
count++; // OK — re-assign được

if (true) {
  let blockScoped = 'chỉ trong đây';
  console.log(blockScoped); // OK
}
// console.log(blockScoped); // ReferenceError

// Dùng let trong for loop — mỗi iteration có scope riêng
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
  // 0, 1, 2 — đúng (var sẽ cho 3, 3, 3)
}
ES6 · Default choiceconst — block scope, immutable binding

const không thể re-assign. Nhưng nếu giá trị là object/array, nội dung bên trong vẫn thay đổi được — chỉ binding là constant.

const — immutable binding, mutable content
const PI = 3.14;
// PI = 3; // TypeError

// Object: binding không đổi, properties có thể đổi
const user = { name: 'Alice', age: 25 };
user.age = 26;    // OK — đổi property
// user = {};    // TypeError — re-assign

// Array: push/pop được, re-assign không được
const items = [1, 2, 3];
items.push(4); // OK
// items = []; // TypeError
→
Rule of thumb: Luôn dùng const mặc định. Chỉ đổi sang let khi cần re-assign. Không bao giờ dùng var.
Kiểm tra nhanh

Đoạn code sau in ra gì?
const cart = ['táo', 'xoài']; cart.push('cam'); console.log(cart.length);

Đúng. const chỉ ngăn re-assign binding. Nội dung array hoàn toàn thay đổi được qua push, pop, splice, v.v.
Bài 2 · Functions

Arrow Functions
cú pháp gọn và this lexical

Arrow function không chỉ là cú pháp ngắn — nó thay đổi cách this hoạt động, giải quyết một trong những bug phổ biến nhất của JS cũ.

ES6Syntax — từ dài đến ngắn
4 cách viết — cùng kết quả
// 1. Function declaration truyền thống
function add(a, b) { return a + b; }

// 2. Function expression
const add = function(a, b) { return a + b; };

// 3. Arrow — đầy đủ
const add = (a, b) => { return a + b; };

// 4. Arrow — implicit return (1 expression)
const add = (a, b) => a + b;

// Return object — phải bọc trong ()
const makeUser = (name) => ({ name, role: 'user' });
makeUser('Alice'); // { name: 'Alice', role: 'user' }
Quan trọngthis — lexical binding

Arrow function không có this riêng — kế thừa this từ scope bên ngoài nơi nó được định nghĩa.

Function thường — this bị mất
const timer = {
  seconds: 0,
  start: function() {
    setInterval(function() {
      // this = window!
      this.seconds++; // BUG
    }, 1000);
  }
};
Arrow function — this được giữ
const timer = {
  seconds: 0,
  start: function() {
    setInterval(() => {
      // this = timer ✓
      this.seconds++; // OK
    }, 1000);
  }
};
→
Trong React/NestJS: Arrow function dùng khắp nơi — event handlers, array methods, useEffect callbacks. Bạn sẽ ít khi cần function keyword.
Hay dùngArrow + Array methods
Pattern phổ biến nhất trong ecommerce
const products = [
  { id: 1, name: 'Áo', price: 200000, inStock: true },
  { id: 2, name: 'Quần', price: 350000, inStock: false },
  { id: 3, name: 'Giày', price: 500000, inStock: true },
];

const available = products.filter(p => p.inStock);
const prices    = products.map(p => p.price);
const total     = products.reduce((sum, p) => sum + p.price, 0);

// Chaining
const names = products
  .filter(p => p.inStock)
  .map(p => p.name);
// ['Áo', 'Giày']
Kiểm tra nhanh

Arrow function khác function thường ở điểm nào quan trọng nhất?

Đúng. Arrow function có lexical this — this được xác định lúc định nghĩa, không phải lúc gọi. Điều này giải quyết rất nhiều bug this trong callbacks.
Bài 3 · Syntax

Destructuring
unpack objects và arrays gọn gàng

Một trong những feature dùng nhiều nhất trong React — props, hook returns, API response handling.

ES6Object destructuring
Object — theo tên field
const user = { name: 'Alice', age: 28, role: 'admin' };

// Cách cũ
const name = user.name;
const age  = user.age;

// Destructuring — 1 dòng
const { name, age, role } = user;

// Đổi tên
const { name: userName, role: userRole } = user;

// Default value khi field là undefined
const { name, avatar = '/default.png' } = user;

// Nested destructuring
const order = { id: 1, customer: { name: 'Bob', city: 'HN' } };
const { customer: { name: custName, city } } = order;
ES6Array destructuring
Array — theo vị trí
const coords = [10.776, 106.700];
const [lat, lng] = coords;

// Skip phần tử bằng dấu phẩy
const [first, , third] = [1, 2, 3];

// Rest — lấy phần còn lại
const [head, ...tail] = [1, 2, 3, 4];
// head=1, tail=[2,3,4]

// Swap variables
let [a, b] = [1, 2];
[a, b] = [b, a]; // a=2, b=1

// useState hook — array destructuring
const [count, setCount] = useState(0);
→
Trong React: const [state, setState] = useState() là array destructuring. const { data, isLoading } = useQuery() là object destructuring. Bạn dùng cả hai hàng trăm lần mỗi ngày.
Pattern hayDestructuring trong function parameters
Props destructuring — React chuẩn
// Không destructure — verbose
function ProductCard(props) {
  return props.name + ' — ' + props.price;
}

// Destructure trong params — clean
function ProductCard({ name, price, inStock = true }) {
  return `${name} — ${price.toLocaleString()}₫`;
}

// NestJS service — destructure API response
async function loadOrder(id) {
  const { data: { order, customer } } = await fetchOrder(id);
  return { order, customer };
}
Kiểm tra nhanh

Kết quả của đoạn này?
const { name, price = 0 } = { name: 'Áo' }; console.log(price);

Đúng. Default value trong destructuring chỉ kích hoạt khi field là undefined. Nếu field là null, default KHÔNG được dùng — null là giá trị explicit.
Bài 4 · Syntax

Spread & Rest ...
3 dấu chấm, 2 công dụng ngược nhau

Cùng syntax ... nhưng làm 2 việc trái ngược: spread mở rộng ra, rest gom lại. Context quyết định.

ES6Spread — mở rộng array/object
Spread operator
// Clone array
const original = [1, 2, 3];
const copy = [...original];

// Merge arrays
const merged = [...original, 4, 5]; // [1,2,3,4,5]

// Clone + update object
const user = { name: 'Alice', age: 25 };
const updated = { ...user, age: 26 }; // override age

// Merge objects — sau ghi đè trước
const defaults = { theme: 'light', lang: 'vi', size: 'md' };
const config   = { size: 'lg', debug: true };
const final    = { ...defaults, ...config };
// { theme:'light', lang:'vi', size:'lg', debug:true }

// Thêm item vào cart — immutable pattern
const addToCart = (cart, item) => [...cart, item];
→
Trong React state: Luôn dùng spread khi update state — không mutate trực tiếp. setUser({...user, age: 26}) thay vì user.age = 26. React dùng reference equality để detect changes.
ES6Rest — gom phần còn lại
Rest trong params và destructuring
// Rest params — nhận nhiều args thành array
const sum = (...numbers) =>
  numbers.reduce((acc, n) => acc + n, 0);
sum(1, 2, 3, 4); // 10

// Rest trong object destructuring
// Lọc sensitive fields — pattern NestJS response
const { id, passwordHash, ...publicData } = userFromDB;
// publicData = { name, email, role } — không có passwordHash

// Rest trong array destructuring
const [first, second, ...rest] = [10, 20, 30, 40];
// first=10, second=20, rest=[30,40]
Kiểm tra nhanh

Trong NestJS, userFromDB có id, name, email, passwordHash. Cách nào đúng để trả về user KHÔNG có passwordHash?

Đúng. Rest destructuring tách passwordHash ra biến riêng và gom phần còn lại vào safeUser. Pattern chuẩn trong NestJS để sanitize response — không mutate object gốc.
Bài 5 · Syntax

Template Literals
& Optional Chaining ?.

Hai feature giúp code sạch hơn và an toàn hơn khi làm việc với data có thể undefined.

ES6Template literals — string interpolation
Backtick strings
const product = { name: 'Áo polo', price: 299000 };

// Cách cũ — nối chuỗi thủ công
const msg = 'Sản phẩm: ' + product.name + ' — ' + product.price + '₫';

// Template literal — gọn và dễ đọc
const msg = `Sản phẩm: ${product.name} — ${product.price.toLocaleString()}₫`;

// Expression bên trong ${}
const discount = 10;
const final = `Sau giảm ${discount}%: ${product.price * (1 - discount/100)}₫`;

// Multi-line string
const html = `
  <div class="product">
    <h2>${product.name}</h2>
    <p>${product.price.toLocaleString()}₫</p>
  </div>
`;
ES2020Optional chaining ?. — truy cập an toàn

Thay vì kiểm tra null/undefined từng bước, ?. trả về undefined ngay khi gặp giá trị null/undefined — không throw error.

?. và ?? (nullish coalescing)
const order = { id: 1, customer: { name: 'Alice' } };
// shipping là undefined

// Cách cũ — dễ crash
const city = order && order.shipping && order.shipping.address
  && order.shipping.address.city;

// Optional chaining — gọn, an toàn
const city = order?.shipping?.address?.city;
// undefined — không throw error

// Kết hợp ?? để có default value
const city = order?.shipping?.address?.city ?? 'Chưa có địa chỉ';

// ?? vs || — khác biệt quan trọng
const price = 0;
console.log(price || 100);  // 100 — 0 là falsy!
console.log(price ?? 100);  // 0  — ?? chỉ check null/undefined

// Optional chaining với method và array
const upper = user?.name?.toUpperCase();
const first = arr?.[0];
→
Trong ecommerce: API response không phải lúc nào cũng đầy đủ. product?.variants?.[0]?.price ?? 0 an toàn hơn nhiều so với access thẳng.
Kiểm tra nhanh

Tại sao nên dùng ?? thay vì || khi set default value cho price?

Đúng. price || 0 sẽ dùng default ngay cả khi price = 0 (vì 0 là falsy). Bug điển hình trong ecommerce khi sản phẩm miễn phí. price ?? 0 chỉ dùng default khi price là null hoặc undefined.
Bài 6 · Modules

ES Modules
import / export — tổ chức code

TypeScript, Next.js, NestJS đều dùng ESM syntax. Học một lần, dùng ở cả frontend lẫn backend.

ESMNamed exports & imports
utils/price.js — named exports
export const formatPrice = (price) =>
  `${price.toLocaleString('vi-VN')}₫`;

export const calcDiscount = (price, pct) =>
  price * (1 - pct / 100);

export const TAX_RATE = 0.1;

// Hoặc export cuối file
const validatePrice = (p) => p > 0;
export { validatePrice };
components/ProductCard.js — imports
// Chỉ lấy cái cần
import { formatPrice, calcDiscount } from '../utils/price';

// Import tất cả vào namespace
import * as PriceUtils from '../utils/price';
PriceUtils.formatPrice(100000);

// Đổi tên khi import
import { formatPrice as fmt } from '../utils/price';
ESMDefault export & dynamic import
Default + dynamic import
// Default export — 1 giá trị chính, thường là component
export default function ProductCard({ name, price }) {
  return `<div>${name}: ${price}</div>`;
}

// Import default — đặt tên tùy ý
import Card from './ProductCard';

// Mix default + named
import ProductCard, { formatPrice } from './ProductCard';

// Dynamic import — lazy loading (Next.js code splitting)
const Chart = await import('./HeavyChart');

// Trong Next.js
import dynamic from 'next/dynamic';
const Chart = dynamic(() => import('./Chart'), { ssr: false });
→
Convention: React components dùng default export. Utilities, hooks, constants dùng named exports. Giúp import rõ ràng và IDE refactoring dễ hơn.
Kiểm tra nhanh

Trong file auth.js: export default AuthService và export const JWT_SECRET = '...'. Import nào đúng?

Đúng. Default export import không có ngoặc nhọn, named export thì có. import DefaultExport, { namedExport } from './file' là cú pháp chuẩn.
Bài 7 · Arrays

Array Methods
map · filter · reduce · find

4 methods này xuất hiện trong mọi codebase. Hiểu chúng sâu là hiểu cách React render list, NestJS transform data, và xử lý API response.

Coremap — transform từng phần tử

Trả về array mới cùng độ dài, mỗi phần tử đã được transform. Không thay đổi array gốc.

map trong ecommerce
const products = [
  { id: 1, name: 'Áo', price: 200000 },
  { id: 2, name: 'Quần', price: 350000 },
];

// Thêm field discountedPrice
const withDiscount = products.map(p => ({
  ...p,
  discountedPrice: p.price * 0.9,
}));

// React — render list
const items = products.map(p =>
  `<li key={p.id}>{p.name}</li>`
);

// Extract IDs
const ids = products.map(p => p.id); // [1, 2]
Corefilter — lọc theo điều kiện
filter — lọc sản phẩm
const products = [
  { id: 1, name: 'Áo',   price: 200000, inStock: true  },
  { id: 2, name: 'Quần', price: 350000, inStock: false },
  { id: 3, name: 'Giày', price: 500000, inStock: true  },
];

const available  = products.filter(p => p.inStock);
const affordable = products.filter(p => p.price <= 300000);

// Xóa item khỏi cart — immutable
const removeFromCart = (cart, itemId) =>
  cart.filter(item => item.id !== itemId);

// Chaining filter + map
const availableNames = products
  .filter(p => p.inStock)
  .map(p => p.name); // ['Áo', 'Giày']
Corereduce — gom thành 1 giá trị
reduce — tính toán cart
const cart = [
  { name: 'Áo',   price: 200000, qty: 2 },
  { name: 'Quần', price: 350000, qty: 1 },
];

// Tổng tiền = Σ (price × qty)
const total = cart.reduce(
  (sum, item) => sum + item.price * item.qty,
  0 // initial value
); // 750000

// Group by category — reduce tạo ra object
const byCategory = products.reduce((acc, p) => {
  acc[p.category] = acc[p.category] || [];
  acc[p.category].push(p);
  return acc;
}, {}); // { top:[...], bottom:[...] }
Corefind · some · every · includes
Các methods hay dùng khác
// find — phần tử đầu tiên match, hoặc undefined
const item = cart.find(i => i.id === 5);

// findIndex — index hoặc -1
const idx = cart.findIndex(i => i.id === 5);

// some — có ÍT NHẤT 1 match?
const hasExpensive = products.some(p => p.price > 400000);

// every — TẤT CẢ đều match?
const allInStock = products.every(p => p.inStock);

// includes — tìm primitive value
const roles = ['admin', 'seller', 'buyer'];
roles.includes('admin'); // true
Bài tập cuối khóa

Tính tổng tiền CHỈ các sản phẩm còn hàng (inStock: true) trong cart. Điền vào chỗ trống:
const total = cart.___().___((sum, i) => sum + i.price * i.qty, 0);

Đúng! filter lấy items còn hàng, rồi reduce tính tổng. Pattern filter().reduce() rất phổ biến trong ecommerce. Bạn đã hoàn thành toàn bộ bài học ES6+ Fundamentals!
